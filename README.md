# Территория Санька: Королевская Битва — лаунчер Arma 3
Локальный лаунчер для лицензионной Arma 3 1.94. Он использует GitHub только для
проверяемой доставки собственных модов и обновлений лаунчера; не обновляет игру
и не подключает её к публичным серверам.

## Что делает

- по умолчанию отмечает `Contact Fuse Drone` и `Канистра с топливом`; при
  включении сверяет версию пакета с манифестом GitHub и автоматически заменяет
  отсутствующий или устаревший PBO проверенным ZIP из папки `mods/`;
- сверяет размер, SHA-256 и безопасную структуру ZIP перед локальной установкой;
- хранит установленный мод отдельно от игры в данных текущего пользователя и
  подключает его через `-mod=`; Arma 3, Steam и BattlEye не изменяются;
- каждая галочка независимо включает мод; при нескольких отмеченных модах их
  локальные папки передаются Arma 3 вместе одним параметром `-mod=path1;path2`;
  при отмеченном, но отсутствующем или загружаемом PBO кнопка «Играть» недоступна;
- запускает с `-world=empty` и `-noSplash`;
- отображает пустой список карт;
- перед запуском проверяет игру и PBO;
- блокирует повторный запуск, если уже есть `arma3_x64.exe`.
- автоматически находит совместимую Arma 3 1.94: сначала проверяет сохранённую
  конфигурацию, затем Steam, реестр Bohemia и стандартные папки;
- хранит только подтверждённый путь в данных приложения пользователя.
- при открытии проигрывает на повторе локальный трек «С территории Санька» на тихой громкости (16%); круглая кнопка с иконкой динамика отключает/включает звук, а нажатие «Играть» останавливает воспроизведение.
- при каждом открытии обязательно проверяет GitHub Releases и обновляет только собственные файлы лаунчера; Arma 3, её мод и зависимости никогда не являются целью обновления;
- открывает интерфейс в собственном окне EXE на базе Windows WebView2, а локальный адрес `127.0.0.1` остаётся внутренним API-интерфейсом, а не вкладкой браузера.
- использует компактное окно 960×640, рассчитанное на экран 720p: сама форма не прокручивается, а растущие списки модов и карт прокручиваются внутри своих плиток.

## Запуск

1. При разработке выполните `pnpm run build`.
2. Откройте `TerritorySanyokLauncher.exe`; скрипт `run-launcher.cmd` автоматически предпочитает этот EXE и остаётся резервным вариантом для разработки.
3. Оставьте отмеченными нужные моды: при первом запуске лаунчер скачает и
   проверит каждый из них из GitHub.
4. Нажмите «Играть» после завершения проверки игры, обновлений и мода.

Если игра не найдена, вставьте путь к её папке в поле «Папка с Arma 3» и нажмите
«Указать путь». Лаунчер принимает только папку, где есть `arma3_x64.exe` версии
1.94; при следующем запуске он снова проверит путь и начнёт поиск заново, если
игра была перенесена. `launcher.config.json` остаётся совместимым резервным
вариантом для уже настроенных копий. Лаунчер рассчитан только на одиночную игру
и контролируемую LAN-сессию.

## Установка для игроков (Windows)

Для обычной установки используйте `TerritorySanyokLauncher-Setup-<версия>.exe` из
GitHub Release. Инсталлятор ставит автономный лаунчер в папку текущего пользователя,
создаёт запись для удаления в Windows и предлагает отдельной галочкой «Создать ярлык
на рабочем столе». Python игроку не требуется. При повторном запуске release-
установщик находит предыдущую версию по идентификатору приложения, обновляет её в
той же папке и предлагает штатно закрыть лаунчер, если он открыт. Установка версии
ниже уже установленной намеренно отменяется.

Инсталлятор намеренно не содержит и не изменяет Arma 3, BattlEye, Steam или
игровые сохранения. При первом использовании лаунчер скачивает собственный PBO
в `%LOCALAPPDATA%\UniversalModder\Arma3ContactFuseLauncher\mods\` в отдельных
каталогах. Для разработки можно указать `mod_build_dirs` в
`launcher.config.json`; указанная папка не заменяется автоматически.

В репозитории нет Arma 3, игровых данных или сохранений. В
`mods/contact-fuse-drone` и `mods/fuel-canister` находятся только наши
распространяемые PBO-пакеты и их манифесты; перед запуском лаунчер проверяет
`addons/umcfd_main.pbo` и `addons/umfc_main.pbo` соответственно.

## Доставка модов через GitHub

Настройки каждого пакета находятся в разделе `mod_sources` файла
`launcher.config.json`:

```json
"mod_sources": {
  "umcfd": { "github_repository": "Solverg/territoriya-sanka-launcher", "ref": "main", "manifest_path": "mods/contact-fuse-drone/mod-manifest.json" },
  "umfc": { "github_repository": "Solverg/territoriya-sanka-launcher", "ref": "main", "manifest_path": "mods/fuel-canister/mod-manifest.json" }
}
```

Манифест указывает версию, ZIP, SHA-256, размер и единственную допустимую
корневую папку. После установки лаунчер хранит рядом с модом собственную
квитанцию версии и хеша; её отсутствие (включая старые установки) вызывает одно
безопасное обновление. Неверный размер, хеш, ZIP-path traversal, символическая
ссылка либо отсутствующий ожидаемый PBO отменяют установку. Для нового билда
обновляйте ZIP и манифест в одном коммите. Старый раздел `mod` остаётся
совместимым только для `umcfd`.

## Обновления лаунчера через GitHub

Репозиторий обновлений — `Solverg/territoriya-sanka-launcher`. В
`launcher.config.json` используется только имя вида `owner/repository`:

```json
"update": {
  "github_repository": "owner/repository",
  "asset_name": "territoriya-sanka-launcher.zip",
  "checksum_asset": "SHA256SUMS.txt"
}
```

Каждый GitHub Release должен иметь тег версии (`v1.0.1`), ZIP-asset с заданным
именем и `SHA256SUMS.txt`. Внутри ZIP допустима одна корневая папка
`launcher/`, содержащая `launcher.py`, `run-launcher.cmd` и
`dist/client/index.html`. Лаунчер сначала проверяет SHA-256 и сохраняет архив
в данных приложения пользователя. Если в проверенном релизе номер выше
текущего, он скачивается, проверяется, устанавливается и сразу перезапускает
лаунчер без отдельного запроса; в интерфейсе показывается ход операции.
`launcher.config.json` и `MODLOG.md` не перезаписываются. Установка не
запускает Arma 3 и не меняет её папку.
